# 🐕 Dog Walks

Учёт прогулок с собакой на двоих: кто гулял, сколько, когда вернулись и что было по дороге.

Прод: http://103.76.53.197/ (закрыт паролем)

---

## Что умеет

**Запись**

- Недельный календарь: 7 дней × 3 слота (утро / день / вечер) и дневной вид для телефона
- Четыре состояния слота: Андрей 🔵 / Ира 🟣 / Оба 🟢 / Никто ⬜
- Длительность, время возвращения, отметка о туалете, заметка
- Панель редактирования правит всё сразу и сохраняет мгновенно, без кнопки «Сохранить»
- Журнал изменений: видно, что и когда правили

**Разбор**

- Наблюдения за день: отклонение от нормы, перерывы между прогулками, серии без отметок
- График по дням со скользящей медианой за 28 дней
- Статистика за период и выгрузка в CSV
- Разбор периода языковой моделью — читает цифры и заметки и описывает, что в них видно

Приложение показывает факты и отклонения, а выводы оставляет человеку: «на 40% меньше обычного», а не «мало гуляли». Медицинских порогов здесь нет и быть не должно.

## Стек

| Слой | Технология |
|---|---|
| Frontend | React 18 + Vite |
| Backend | Node.js + Express |
| База | SQLite (`better-sqlite3`) |
| Модель | любой OpenAI-совместимый провайдер (используется Yandex AI Studio) |
| Хостинг | Yandex Cloud, Ubuntu 22.04 |
| Проксирование | nginx |
| Процесс-менеджер | PM2 |

Версия Node зафиксирована в [`.nvmrc`](.nvmrc) — одна и та же локально, в CI и на сервере.

Бэкенд разделён так, чтобы `app.js` можно было импортировать в тесты и подсунуть ему базу в памяти. Порт слушает только `server.js`.

Аналитика вынесена из эндпоинтов в `analytics/` и работает не с колонками базы, а с промежуточным представлением (`normalize.js`). Когда участников станет больше двух, поменяется только адаптер — метрики этого не заметят.

## Запуск локально

Нужен Node версии из `.nvmrc`:

```bash
nvm use
```

Установка и первый запуск:

```bash
cd code/backend
cp .env.example .env
npm install
npm run dev
```

В другом окне:

```bash
cd code/frontend
npm install
npm run dev
```

- Frontend: http://localhost:5173
- API: http://localhost:3000/api

База создастся сама при первом старте, миграции применятся автоматически. Блок AI-разбора не появится, пока в `.env` не заполнены ключи модели — это нормально, остальное работает без них.

## Тесты

```bash
cd code/backend && npm test
cd code/frontend && npm test
```

Тесты бэкенда работают с базой в оперативной памяти и реальных данных не трогают.

Тесты фронтенда запускаются в зоне `Europe/Moscow` — это задано в npm-скрипте намеренно. В UTC ошибки с часовыми поясами не воспроизводятся вовсе, и зелёные тесты ничего не доказывают.

## Как вносить изменения

`main` защищён, напрямую в него не пушим. Любая правка едет через ветку и Pull Request.

```bash
git checkout main && git pull
git checkout -b feat/название

# ...правки...

cd code/backend && npm test && cd ../frontend && npm test && cd ../..
git add -A
git commit -m "feat: что сделал"
git push -u origin feat/название
```

Дальше открыть PR, дождаться зелёного CI, влить. После вливания:

```bash
git checkout main && git pull
git branch -d feat/название
```

Префиксы коммитов: `feat:`, `fix:`, `chore:`, `refactor:`, `test:`, `docs:`.

## API

Все эндпоинты кроме `/api/health` закрыты Basic Auth на уровне nginx.

| Метод | Endpoint | Описание |
|---|---|---|
| `GET` | `/api/health` | Статус сервиса, используется автодеплоем |
| `GET` | `/api/walks?from=&to=` | Прогулки за период |
| `PUT` | `/api/walks/:date/:slot` | Записать прогулку |
| `GET` | `/api/stats?from=&to=` | Статистика за период |
| `GET` | `/api/summary?from=&to=` | Сводка: нагрузка по людям, дни с записями |
| `GET` | `/api/series?from=&to=` | Ряд по дням для графика: факт и медиана |
| `GET` | `/api/insights?date=` | Наблюдения за день с отклонениями от нормы |
| `GET` | `/api/changes?date=&slot=` | Журнал изменений записи |
| `GET` | `/api/ai-report?from=&to=` | Сохранённый разбор периода |
| `POST` | `/api/ai-report` | Сгенерировать разбор заново |
| `GET` | `/api/export?from=&to=` | Выгрузка в CSV |

Даты в формате `YYYY-MM-DD`. Слоты: `morning`, `afternoon`, `evening`. Значения `person`: `andrey`, `ira`, `both`, `none`. Длительность — от 0 до 480 минут.

Генерация разбора — `POST`, а не `GET`, намеренно: запрос стоит денег и меняет состояние, такое не должно случаться от перехода по ссылке.

### Схема данных

Таблица `walks`:

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER PK | авто-инкремент |
| `walk_date` | TEXT | дата `YYYY-MM-DD` |
| `slot` | TEXT | `morning` / `afternoon` / `evening` |
| `person` | TEXT | `andrey` / `ira` / `both` / `none` |
| `duration` | INTEGER | минуты, `NULL` — не засекали |
| `ended_at` | TEXT | время возвращения, `NULL` — неизвестно |
| `poop` | TEXT | `yes` / `no` / `NULL` — не проверяли |
| `comments` | TEXT | заметка |
| `updated_at` | TEXT | время последнего изменения |

Уникальность по паре `(walk_date, slot)` — на один слот одна запись.

Ещё две таблицы: `walk_changes` — журнал правок, `ai_reports` — сохранённые разборы вместе с моделью, версией промпта и хешем его текста.

### Что означает отсутствие данных

`NULL` и значение — разные факты, и смешивать их в статистике нельзя.

| Поле | `NULL` | Значение |
|---|---|---|
| `duration` | не засекали | число минут |
| `poop` | не проверяли | `yes` / `no` |
| `ended_at` | время неизвестно | момент возвращения |

Отсутствие строки — четвёртый случай, и он не то же самое, что `person='none'`. Нет строки — за этот слот ничего не заполняли. `none` — заполнили и отметили, что никто не выходил.

Ноль в `duration` не встречается с миграции v4 — он всегда означал «нет данных», а не «ноль минут».

### Миграции

Схема версионируется через `PRAGMA user_version`. Миграции лежат в `code/backend/src/migrations.js` и применяются при старте сервера: база сама знает, на каком она шаге, и докатывает недостающее.

Новые миграции добавляются **только в конец** массива. Уже существующие менять нельзя — они применены на проде, и правка задним числом разведёт схемы.

### Работа с датами

Дата прогулки — календарный день по местным часам, а не момент времени. Поэтому во фронтенде нет ни одного вызова `toISOString()` для дат: он переводит в UTC, и в UTC+3 объект «10 августа 01:00» превращается в строку «2026-08-09». Страница при этом подписана десятым числом локальным форматтером — и читает данные за девятое.

Для преобразований есть `dateUtils.formatDate` и `dateUtils.parseDate` в `services/api.js`, обе работают по местному календарю. Тесты на них лежат в `code/frontend/tests/dates.test.js`.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | порт бэкенда | `3000` |
| `DB_PATH` | путь к файлу SQLite | `./database/walks.db` |
| `APP_VERSION` | версия в ответе `/api/health` | `dev` |
| `LLM_BASE_URL` | адрес OpenAI-совместимого API | — |
| `LLM_API_KEY` | ключ, живёт только на сервере | — |
| `LLM_MODEL` | идентификатор модели | — |
| `LLM_TEMPERATURE` | температура генерации | `0.3` |
| `LLM_MAX_TOKENS` | потолок длины ответа | `2000` |
| `LLM_PROMPT_FILE` | путь к файлу промпта | `prompts/report-system.md` |

Локально задаются в `code/backend/.env` (не коммитится, шаблон — `.env.example`). На сервере файл лежит там же и читается самим `server.js`: способ запуска на это не влияет, PM2 в режиме cluster флаги вида `--env-file` воркеру не передаёт.

Ключ модели никогда не попадает во фронтенд: браузер ходит в наш бэкенд, бэкенд — к модели.

### Промпт

Текст системной инструкции — в `code/backend/prompts/report-system.md`. Он часть логики и версионируется вместе с кодом. Подбирать формулировки прямо на сервере можно через `LLM_PROMPT_FILE`, указав файл вне репозитория: деплой делает `git reset --hard` и правку внутри проекта сотрёт. Подробности — в разделе 8.5 шпаргалки.

## Методика расчётов

**Базовая линия — медиана за 28 дней.** Четыре полные недели: каждый день недели попадает в выборку четырежды, поэтому перекос выходных усредняется сам собой.

**Медиана, а не среднее.** Одна прогулка на три часа заметно сдвигает среднее и почти не двигает медиану.

**Будни отдельно от выходных.** Если однотипных дней в окне меньше четырёх, берём все подряд.

**Минимум 14 дней.** Пока данных меньше, сравнения не показываются вовсе. Поэтому после долгого перерыва — например, отпуска — линия медианы пропадает примерно на месяц: сравнивать не с чем, и честнее об этом молчать, чем показать цифру, построенную на трёх днях.

**Целевой день в выборку не входит** — день не сравнивается сам с собой.
